## 😱 단일 컴포넌트를 넘어, 의존성이 뒤엉킨 레거시 파일의 공포

1회차에서 우리는 사내 코드를 숨기는 데이터 분리 질의법을 배웠고, 2회차에서는 Cursor의 빈 작업 공간(New Window)을 열어 단일 커스텀 훅과 컴포넌트를 안전하게 뽑아내는 실전을 다루었습니다.

하지만 실제 출근해서 우리가 마주하는 진짜 괴물은 단일 컴포넌트가 아닙니다. 수년 전 퇴사한 전임자가 만들고 간, **수백 줄짜리 거대하고 낡은 레거시 파일**입니다. 상태 관리 라이브러리는 꼬여 있고, UI 마크업과 비즈니스 로직이 한 파일에 수백 줄로 떡져 있어 2회차에서 했던 것처럼 프롬프트 몇 줄로 뼈대만 뽑아내기가 불가능해 보입니다. 사내망 보안 규정 때문에 이 복잡한 파일 자체를 외부 AI에 통째로 넘길 수도 없어 개발자의 고통은 배가 됩니다.

3회차에서는 2회차의 Cursor 격리 창 활용법을 **레거시 파일 단위**로 확장합니다. 실제 사내 비즈니스 자산(서버 주소, 고유 변수명)은 단 1초 만에 마스킹하여 완벽히 숨기고, Cursor 에디터 고유의 강력한 기능인 파일 참조(`@file`) 및 웹 검색 참조(`@web`) 기능을 복합적으로 활용해 복잡한 레거시 파일을 통째로 안전하게 체질 개선하는 고도화된 실전 오퍼레이션을 소개합니다.

## 🔗 [실전 유스케이스 3] 멀티 컨텍스트 제어: Cursor @file과 @web을 결합한 3단계 오퍼레이션

실무에서 바로 써먹을 수 있는 **'보안 준수형 레거시 리팩토링 오퍼레이션'** 3단계 프로세스입니다.

### 1단계: 격리 창에 파일 복사 및 초고속 마스킹

사내 메인 프로젝트에서 리팩토링이 필요한 낡고 긴 소스코드 텍스트를 통째로 복사(Ctrl+C)합니다. Cursor의 빈 작업 공간(New Window)을 열고, 임의의 파일(`LegacyComponent.tsx`)을 만들어 붙여넣습니다.

그 후, 파일 내부에 있는 사내 도메인 주소, 특정 기밀 API Key, 고유 제품 코드명 등만 가상의 텍스트(`"https://mock.com"`, `CompanyProductItem` → `MockItem`)로 바꿉니다. 비즈니스 자산이 소거된 순수한 코드 논리 구조만 남기는 과정입니다.

### 2단계: Cursor @file 및 @web 복합 참조를 이용한 일괄 리팩토링 요청

Cursor의 사이드바 Chat 창을 엽니다. 단순히 텍스트로 설명하는 것을 넘어, 에디터 내의 파일을 직접 읽게 만드는 `@file` 기능과 최신 기술 동향을 구글링하여 반영하는 `@web` 기능을 동시에 조합하여 강력한 컨텍스트 리시브 환경을 구축합니다.

**💻 Cursor 격리 창 프롬프트 타이핑**

```
[요구사항]
@LegacyComponent.tsx 이 파일은 과거에 작성된 거대한 검색 필터 컴포넌트입니다. 사내 중요 정보는 이미 가상 텍스트로 마스킹 처리되었습니다.

1. @web 을 통해 최신 Zustand 라이브러리의 V5 마이그레이션 공식 도큐먼트 가이드라인을 검색 및 참조해 주세요.
2. 현재 이 코드는 복잡한 낡은 클래스형 코드로 짜여 있어 불필요한 전체 리렌더링이 심하게 발생하고 있습니다. 검색한 최신 Zustand v5의 셀렉터 구조 및 원자적 상태 관리 규격을 적용해 런타임 성능을 극대화해 주세요.
3. 가독성과 유지보수를 위해 비즈니스 로직(상태 관리)은 별도의 커스텀 훅으로 완전히 분리(Presentational & Container 패턴)하여, 리팩토링된 신규 파일 2개로 나누어 완성도 높게 출력해 주세요.
```

### 3단계: Cursor의 출력 코드 검증 및 사내망 결합

**🛠️ Cursor 출력 결과**

Cursor는 마스킹된 코드와 실시간 구글링된 명세서를 기반으로 꼬여있던 의존성을 완벽하게 발라내어, 최신 마이그레이션 규격이 적용된 정돈된 신규 파일 2개를 안정적으로 반환합니다.

```typescript
// [파일 1] 최신 Zustand v5 마이그레이션이 반영된 커스텀 훅 파일 (useFilterContainer.ts)
import { create } from 'zustand';

interface FilterState {
  keyword: string;
  setKeyword: (text: string) => void;
}

// @web으로 검색한 최신 규격에 맞춰 원자적 셀렉터 결합이 가능한 스토어 설계
export const useFilterContainer = create<FilterState>((set) => ({
  keyword: '',
  setKeyword: (text) => set({ keyword: text }),
}));
```

```typescript
// [파일 2] Presentational 패턴으로 로직이 완벽히 분리된 UI 컴포넌트 파일 (NewFilterComponent.tsx)
import { useFilterContainer } from './useFilterContainer';

export function NewFilterComponent() {
  // 필요한 상태만 셀렉터로 정밀하게 분리 호출하여 불필요한 부모 리렌더링 방지
  const keyword = useFilterContainer((state) => state.keyword);
  const setKeyword = useFilterContainer((state) => state.setKeyword);

  return (
    <div role="search" className="search-container">
      <label htmlFor="search-input">검색어 입력</label>
      <input
        id="search-input"
        type="text"
        value={keyword}
        onChange={(e) => setKeyword(e.target.value)}
      />
    </div>
  );
}
```

## 🛡️ 블랙박스 코드의 역습 방지: 사내망 결합 전 '부작용(Side Effect) 선제 감사'

Cursor가 뽑아준 코드가 아무리 깔끔해 보여도, 이를 검증 없이 사내 프로젝트에 냅다 붙여넣는 것은 위험합니다. 프런트엔드 개발자는 코드를 복사하기 전, 격리 창 내부에서 AI가 놓쳤을지 모르는 **'런타임 부작용'**을 한 번 더 감사(Auditing)해야 합니다.

**💻 격리 창 내부 2차 훅 검증 요청 프롬프트:**

```
위에서 네가 리팩토링하여 생성한 [파일 1]과 [파일 2]의 구조를 다시 감사해 주세요.
특히 브라우저 환경에서 `useEffect`나 이벤트 리스너가 누수(Memory Leak)를 유발할 가능성이 없는지, 혹은 Zustand 상태 변경 시 의도치 않은 객체 참조 깨짐으로 인해 무한 루프 렌더링이 발생할 트리거가 없는지 날카롭게 검증하고 '이상 없음'을 증명하는 리포트를 짧게 작성해 줘.
```

이 과정을 거치면 AI는 스스로 코드를 다시 한 바퀴 돌려보며 "객체 리터럴 반환 대신 원시 값을 반환하므로 안전하다", 혹은 **"이벤트 클린업 코드가 누락되었으니 보완한다"**라며 코드를 한 층 더 견고하게 업그레이드해 줍니다.

검증이 끝난 안전한 코드들을 그대로 복사해 사내 진짜 프로젝트 워크스페이스로 가져옵니다. 처음에 보안을 위해 마스킹했던 가상의 주소나 사내 고유 API 함수만 실제 내부 변수로 다시 연결해 주면 리팩토링이 끝납니다. 수 시간이 걸릴 노가다 분석과 분리 작업을 **보안 사고 위험 0%** 상태에서 단 수분 만에 완수하는 오퍼레이션입니다.

## 🎬 Epilogue: 3부작 연재를 마치며 – 프런트엔드가 나아갈 길

총 3회차에 걸친 칼럼 시리즈를 통해 우리는 보안이라는 거대한 장벽 속에서 AI를 영리하게 지배하는 방법을 살펴보았습니다.

* **1회차:** 로컬망 보안 규정을 깨지 않고 AI의 뇌를 빌려 쓰는 **'데이터 분리 질의'**의 기본 원칙
* **2회차:** Cursor 격리 창을 활용해 단일 기능(컴포넌트, 웹 접근성)을 안전하게 뽑아내는 법
* **3회차:** 거대하고 낡은 레거시 파일을 격리 창으로 복제하여 `@file`과 `@web` 기능으로 통째로 뜯어고치는 실전 오퍼레이션

AI 시대에 엔지니어의 진짜 경쟁력은 키보드를 빠르게 두드려 코드를 많이 타이핑하는 것이 아닙니다.

회사 보안 규정이라는 단단한 제약 조건 속에서도 문제를 영리하게 격리하고 복제하여 AI에게 일 시킬 환경을 만드는 **'문맥 제어력(Context Control)'**, AI가 뱉어낸 코드를 사내 코드에 안전하게 접착시키는 **'융합 능력'**, 그리고 블랙박스 코드의 결함을 잡아내는 **'아키텍처 감사 역량'**입니다. 이 무기를 손에 쥔 프런트엔드 개발자는 어떤 인프라 제약 속에서도 압도적인 생산성을 증명해 낼 것입니다.
